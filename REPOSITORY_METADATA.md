# Repository metadata and discoverability checklist

GitHub's **About** description and repository topics are the highest-value
discoverability fields for this project. They must be set in GitHub repository
settings by an authenticated owner; Markdown alone cannot set them.

## Recommended GitHub description

> Freshness-aware industrial IoT and edge event protocol for resilient telemetry, offline replay, MQTT interoperability, and safe device commands.

## Recommended topics

```text
industrial-iot
iot-protocol
mqtt
edge-computing
telemetry
offline-first
store-and-forward
device-management
event-driven
industrial-automation
iot-security
smart-city
fleet-management
remote-monitoring
python
```

Add `arduino` or `smart-feeder` only after an Arduino reference implementation
is added and tested, so search metadata remains accurate.

## GitHub setup steps

1. Open the repository on GitHub.
2. In the right-side **About** panel, select the settings icon.
3. Paste the recommended description.
4. Add the relevant topics above.
5. Add a website only after the project owns and publishes one.
6. Upload an owner-approved social-preview image only after the name, licence,
   and brand are approved.

## What strengthens discovery without misleading users

- A descriptive README with concrete use cases and runnable examples.
- Stable, versioned documentation and a machine-readable schema.
- Accurate README headings that include the real terms users search for:
  industrial IoT, MQTT, telemetry, offline replay, edge computing, and device
  commands.
- Real release notes, CI results, field evidence, and independent
  interoperability reports.

Do not use claims such as “global standard,” “production ready,” “best,” or
“replaces MQTT” until independent evidence and formal adoption support them.
